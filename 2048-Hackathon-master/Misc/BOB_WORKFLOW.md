# BOB Workflow — 2048 Accessibility Update

A detailed record of everything investigated, diagnosed, and fixed during the accessibility pass on this codebase. Written as a narrative so future contributors can understand not just what changed, but why each decision was made.

---

## 1. Codebase Orientation

Before touching anything, the full project was mapped:

- **`index.html`** — single entry point, no framework, loads all scripts at the bottom of `<body>`
- **`js/game_manager.js`** — core game logic (move, merge, win/lose detection, score)
- **`js/grid.js`** — 4×4 data model
- **`js/tile.js`** — individual tile data (position, value, merge history)
- **`js/html_actuator.js`** — DOM renderer: wipes and rebuilds the tile layer after every move
- **`js/keyboard_input_manager.js`** — keyboard and touch input; uses a simple pub/sub `emit`/`on` system
- **`js/local_storage_manager.js`** — persistence of score and game state
- **`style/main.scss`** + **`style/main.css`** — all layout and colour; responsive breakpoint at 520px; tile colours generated by a `@while` SCSS loop at compile time

The architecture uses plain ES5 constructor functions with prototype methods — no classes, no modules, no build step required to play. `GameManager` accepts its four collaborators (input, actuator, storage, grid) as constructor arguments — a simple dependency injection pattern that makes each piece independently replaceable.

## 2. Accessibility Audit

A systematic audit was run across all files against WCAG 2.1 AA. Findings were grouped by severity.

### 🔴 Critical (6 issues)

**No ARIA semantics on the game board.**
The entire `.game-container`, `.grid-container`, and `.tile-container` were unsemantic `<div>` elements. A screen reader user landing on the page had no signal that a game was present, and received no information when tiles moved.

**Moves never announced.**
`HTMLActuator.actuate()` wipes the `.tile-container` and rebuilds it on every move, but there was no `aria-live` region anywhere. Screen readers received no notification of what changed.

**Win/loss message never announced.**
The `.game-message` overlay is hidden with `display: none` and revealed by adding a CSS class. The `<p>` inside it was populated with "You win!" or "Game over!" by JS, but with no `role="alert"` or `aria-live`, screen readers never heard it.

**Score labels invisible to AT.**
The "Score" and "Best" labels on the score boxes existed only as CSS `::after` pseudo-element content. Pseudo-element content is not reliably exposed to the accessibility tree. A screen reader read the score boxes as just `"0"` and `"0"`.

**Buttons not keyboard-accessible.**
All three action buttons (`New Game`, `Keep going`, `Try again`) were `<a>` tags with no `href`. An anchor without `href` is not focusable and not exposed as a button in the accessibility tree. Keyboard users could not reach or activate them at all.

**Zoom blocked on mobile.**
The viewport meta tag included `maximum-scale=1, user-scalable=no` — a direct WCAG 1.4.4 violation that prevents low-vision users from pinching to zoom.

### 🟠 Serious (4 issues)

- Body text colour `#776E65` on background `#faf8ef` — contrast ratio ~3.9:1, below the 4.5:1 AA minimum
- Score label pseudo-content `#eee4da` on `#bbada0` — contrast ~1.3:1
- No `prefers-reduced-motion` support — all four animations run unconditionally
- No on-screen directional controls for touch users who cannot swipe

### 🟡 Moderate (4 issues)

- Missing `lang="en"` on `<html>`
- `target="_blank"` links with no warning and no `rel="noopener noreferrer"`
- Decorative `<hr>` elements announced as "separator" by some screen readers
- Focus not moved to the win/loss overlay when it appears

## 3. ARIA Fixes

### `index.html`

**`lang="en"` on `<html>`.**
Screen readers use this attribute to select the correct pronunciation engine. Without it, content may be read in the wrong language voice.

**Score containers.**
Added `role="status"`, `aria-live="polite"`, and `aria-label="Score: 0"` / `aria-label="Best score: 0"` as initial values. The `aria-label` is kept live by JS on every update. This replaces the CSS `::after` label as the accessible name.

**`New Game` button.**
Changed from `<a>` to `<a role="button" tabindex="0">`. A real `<button>` element would have been cleaner, but changing the tag would require CSS changes. The `role` and `tabindex` together make it keyboard-focusable and expose it correctly in the accessibility tree.

**Game container.**
Added `role="application"` and `aria-label="2048 game board"`. The `application` role signals to screen readers that arrow keys are used for game interaction, not for reading navigation.

**Win/loss overlay.**
Added `role="alert"` and `aria-live="assertive"`. This causes screen readers to interrupt whatever they are currently speaking and announce the result immediately.

**Grid background cells.**
Added `aria-hidden="true"` to `.grid-container`. The 16 static background cells are pure decoration — they carry no game information and previously added meaningless noise to the AT tree.

**Tile container.**
Added `aria-live="polite"` and `aria-atomic="false"`. Polite means announcements wait until the current speech finishes. `aria-atomic="false"` means only new or changed nodes are read — not the entire board on every move.

**In-overlay buttons.**
Added `role="button"` and `tabindex="0"` to `Keep going` and `Try again` for the same reasons as `New Game`.

### `js/html_actuator.js`

**Tile `aria-label`.**
`addTile()` now accepts an optional `ariaHidden` flag. For normal tiles, a label is set: `tile.value + " at row " + finalPos.y + " column " + finalPos.x`. This gives screen reader users a complete description of every tile's value and board position.

**Merge ghost tiles.**
When two tiles merge, the renderer creates the merged result tile and also re-renders the two source tiles briefly for the animation. Those source tiles are now passed `ariaHidden = true` and receive `aria-hidden="true"` — they are visual-only and the merged tile already represents the result.

**Score `aria-label` kept live.**
`updateScore()` now calls `this.scoreContainer.setAttribute("aria-label", "Score: " + this.score)` after each update. The `+N` score delta element gets `aria-hidden="true"` — the score label update already communicates the new total.

**Best score `aria-label` kept live.**
`updateBestScore()` does the same for the best score container.

**Focus on game end.**
`message()` now sets `tabindex="-1"` on the overlay and calls `.focus()` on it. This moves keyboard focus to the overlay so users immediately land on the action buttons, and triggers the `role="alert"` announcement.

### `js/keyboard_input_manager.js`

**Enter and Space activation.**
`bindButtonPress()` previously only added `click` and `touchend` listeners. `<a role="button">` elements do not natively fire `click` on Space — only on Enter in some browsers. A `keydown` listener was added that calls the bound handler on key codes 13 (Enter) and 32 (Space). The `bound` function reference is shared across all three listeners so they can all be cleanly bound at once.

## 4. High Contrast Mode

### Design decisions

Rather than inverting colours or going greyscale, the approach was to give each tile its own unique dark hued background. The hues follow a full colour wheel sweep — slate, navy, teal, green, yellow-green, amber, orange, red-orange, crimson, magenta, violet — so that no two adjacent tile values share a hue family. This means the board is navigable even for users with colour vision deficiencies, because the number inside is always readable as a fallback.

All 11 tile colour combinations were verified to meet WCAG AA (≥4.5:1 white text on the chosen dark background).

Focus rings were changed from white to **yellow (`#ffff00`)**. Yellow on black is one of the highest-contrast combinations available and is the standard indicator used by OS-level forced-colour accessibility modes (Windows High Contrast, macOS Increase Contrast).

### Architecture

The mode is implemented as a separate stylesheet (`style/high-contrast.css`) that activates when `<body>` carries the class `high-contrast`. This approach:
- Keeps the original stylesheet completely untouched
- Requires no build step — plain CSS, loaded alongside `main.css`
- Follows the same pattern as OS-level forced-colour modes
- Is easy to disable or extend

A `<button class="hc-toggle">` was added above the game board. A native `<button>` was used here (not `<a role="button">`) because it is a stateful toggle control with `aria-pressed` — a use case where the native element's built-in behaviour (keyboard activation on both Enter and Space, correct implicit role) removes the need for any extra JS.

The toggle script (`js/high_contrast.js`) is a self-contained IIFE that:
1. Reads `localStorage` on load and applies the saved preference synchronously — before `requestAnimationFrame` fires — so returning users see the correct mode immediately with no flash
2. On click: toggles the body class, flips `aria-pressed`, updates the button label between "High contrast" and "Standard mode"
3. Saves the new preference to `localStorage`

### The `box-sizing` problem

Every element that gains a `border` in HC mode must also declare `box-sizing: border-box`, or the border grows the element *outward* — changing its outer dimensions and breaking layout. This was non-obvious for three elements:

- **`.game-container`** — a `2px border` without `border-box` makes the board `504×504px`. The tile position classes (generated by the SCSS `@for` loop at compile time) are calculated for exactly `500×500px`, so tiles at position 4,4 overflow.
- **`.grid-cell`** — a `2px border` without `border-box` makes each cell `4px` wider and taller. Four cells plus three gaps per row exceed the row width and wrap.
- **`.tile .tile-inner`** — a `2px border` without `border-box` eats into the tile face; large numbers clip at the edges.

`box-sizing: border-box` was applied to all three. The score boxes are a special case (see below).

### The score box `height` trap

The score box rule in `main.css` sets `height: 25px` — but this is the **content-box height** (the original SCSS variable `$height: 25px`). The actual rendered height is `25 + 15 + 15 = 55px` because of `padding: 15px 25px`. The `::after` label sits inside this padding space at `top: 10px`, and the number sits in the content area below.

Applying `box-sizing: border-box` here collapses the **total** box to `25px`, crushing the padding to zero and hiding both the label and the number entirely. The fix is to leave the score boxes at their natural content-box sizing and instead use a negative margin (`margin: 6px -2px 0`) to absorb the `2px` border so it does not shift the surrounding layout.

### Button `line-height` after border

The buttons have `height: 40px; line-height: 42px`. In the base theme there is no border, so the content fills all 40px and the slight `line-height` overhang gives optical vertical centering. With `box-sizing: border-box` and a `2px border`, the content area shrinks to `40 − 4 = 36px`, but `line-height: 42px` remained unchanged — the text was taller than its box and overflowing visibly. Fix: `line-height: 36px` in HC mode for all bordered buttons.

### Border radius on tiles

The base `.tile-inner` rule sets `border-radius: 3px`. The HC override was adding a `border` without also declaring a `border-radius`. This produced a square-cornered border wrapped around a rounded background fill — visibly mismatched corners on every tile. Fix: `border-radius: 3px !important` added to the base HC tile rule that all per-value rules inherit.

## 5. Layout Fix: `.restart-button` Duplicate `display`

During the HC work it was discovered that `.restart-button` in `main.css` had two `display` declarations: `display: inline-block` (from the compiled `@mixin button` include) followed immediately by `display: block`. The second declaration silently overwrote the first. Since `.above-game-buttons` is a flex container, `display: block` children do not participate in flex alignment — they collapsed. Removing the redundant `display: block` lets both the toggle and "New Game" button sit as proper flex items, correctly centred side by side. The same duplicate was removed from `main.scss` to keep source and compiled output in sync.
